# Extension Plan: Deeper Model Understanding & Cross-Architecture Probing

> **Status: three slices implemented; rest deferred.** A user-confirmed subset of this plan has been built across two passes (see `CLAUDE.md` Architecture section and `git log` for the actual changes): pass one — the shared embedding-layer refactor, `TokenClassificationVisualizer`, `QuestionAnsweringVisualizer`, Integrated Gradients, Logit Lens, and Attention Rollout + entropy/distance metrics; pass two — Activation Patching / Causal Tracing; pass three (2026-10-14) — an audit that fixed three silent-wrong-number bugs (Marian `embed_scale`, QA `token_type_ids`, logit-lens double norm; see the inline **Audit** notes) and two shape/type bugs (generative saliency was `[seq, hidden]`; a one-token input gave a string, not a token list), then faithfulness metrics. Each has a smoke test and an analytically-checkable regression test. Vision support, linear probing, cross-model comparison, and the Streamlit app were deliberately **not** attempted — each is a separate large effort in its own right, not a sub-task of one implementation pass. Status markers are inline below; unmarked items are still-accurate future work, not implemented.
>
> A linear-probing idea was considered for pass two first (probing representations for "refusal") but ruled out before any design/implementation work: this project's models (`distilgpt2`, tiny BERT/GPT-2 checkpoints, MarianMT) are all base/non-aligned — none exhibit refusal behavior to probe for, and building that experiment properly needs a chat-aligned model plus a curated harmful/benign prompt dataset, a materially different (and more sensitive) undertaking than anything else in this doc. Linear probing itself is still open future work below, just not for that specific target.

This is a **post-bug-fix roadmap**. It assumes the fixes in `ASSESSMENT.md` / the current fix plan have landed: `ClassificationVisualizer`, `GenerativeVisualizer`, and `Seq2SeqVisualizer` correctly compute gradient saliency and real (not hook-garbage) per-layer attention and hidden states for BERT-like, GPT-like, and Marian/M2M100-like models. This plan expands scope in two directions — more architectures, and more interpretability techniques beyond saliency + raw attention — and sequences them so the second doesn't just re-multiply the bug surface the first phase closes.

## Phase 1 — Generalize architecture support

The current design is three hand-copied subclasses, one per architecture family, each re-implementing the same tokenize → embed → forward → backward skeleton (already flagged in `ASSESSMENT.md` as the reason bug #1 could exist at all — a mistake in one copy doesn't show up in the others until someone diffs them). Before adding more architectures, close that gap:

- ✅ **DONE** — **Extract a shared, tested embedding-layer helper** on `BaseVisualizer` that dispatches on `model.config.is_encoder_decoder` rather than relying on each subclass to independently get `model.get_input_embeddings()` vs `model.get_encoder().embed_tokens` right. Implemented as `BaseVisualizer._input_embeddings()` (not the `_get_input_embedding_layer()` name originally proposed here — it returns the embedding tensor directly rather than the layer, since that's all every call site needed). **Audit 2026-10-14:** the first version omitted Marian's `embed_scale` (max logit difference 13.9) and dropped `token_type_ids` for QA. Both are now fixed. A parametrized test now compares the real saliency forward pass with `model(**inputs)` for every visualizer type.
- ✅ **DONE** — **Token classification & QA visualizers** — implemented as `TokenClassificationVisualizer` (saliency = sum of each token's own predicted-label logit) and `QuestionAnsweringVisualizer` (saliency = predicted span's start+end logit; takes `(question, context)` rather than a single string, so it necessarily has its own `analyze`/`compute_saliency`/`compute_attention` signature — see `CLAUDE.md`).
- **DEFERRED** — **Vision support** (`ViTVisualizer` / `CLIPVisualizer`) — not attempted. Still correct as written: this is the first architecture that breaks the "tokens on an axis" assumption in every `plot_*` method, needs new deps (`torchvision`/`Pillow`) and a new image-preprocessing path, and deserves its own dedicated design pass rather than being bundled into a text-only slice.
- **DEFERRED (descoped, not just postponed)** — **A dedicated "compatibility test matrix" as its own CI concept** — not built as a separate framework. In practice this pass just added one smoke test per new visualizer class to the existing `tests/test_visualizers.py`, which already serves the same purpose without new infrastructure.

## Phase 2 — Deeper probing techniques (beyond gradient saliency + raw attention)

Everything here reuses the per-layer hidden-state/attention capture that the bug fix already establishes (`self.attention_weights` / `self.layer_outputs` populated from real `outputs.attentions` / `outputs.hidden_states`), so it should land after Phase 1's shared-embedding refactor, not before:

- ✅ **DONE** — **Integrated Gradients via Captum** — implemented as `compute_integrated_gradients()` on `ClassificationVisualizer` and `GenerativeVisualizer` (zero-embedding baseline, same target logit `compute_saliency` uses). The completeness-axiom check this doc proposed is exactly what's tested: Captum's `convergence_delta` is asserted near-zero. Not yet added to `Seq2SeqVisualizer`/`TokenClassificationVisualizer`/`QuestionAnsweringVisualizer` — straightforward to extend following the same pattern, just not done in this pass.
- ✅ **DONE** — **Attention rollout** — implemented as `BaseVisualizer.compute_attention_rollout()`, generic across every visualizer type (reuses `self.attention_weights`, already correctly populated — no new forward pass). "Attention flow" (the more expensive max-flow variant Abnar & Zuidema also describe) was not implemented, only the matrix-multiplication rollout.
- ✅ **DONE** — **Logit lens** — implemented as `GenerativeVisualizer.compute_logit_lens()`. One caveat not anticipated in the original bullet: the final-norm step needs an architecture-specific lookup (`self.model.base_model.ln_f`, GPT-2-style); it's applied when found and skipped (not faked) otherwise, so it's not yet guaranteed correct for non-GPT-2-style generative architectures. **Audit 2026-10-14:** the first version applied `ln_f` two times to the last layer (GPT-2 returns that layer already normed). The test did not detect it, because `tiny-gpt2` has a hidden size of 2. The test now uses `distilgpt2`.
- ✅ **DONE** — **Activation patching / causal tracing** — implemented as `compute_activation_patch(clean_text, corrupted_text, layer, position)` on `ClassificationVisualizer`/`GenerativeVisualizer`, plus generic `BaseVisualizer.compute_activation_patch_sweep()`/`plot_activation_patch_sweep()` for the full layer-by-position heatmap. Scoped exactly as this doc anticipated needing: single clean/corrupted pair (must tokenize to equal length), single-position patching, "noising" direction (patch corrupted activations into the clean run), normalized restoration-of-probability metric. Verified via an exact (`torch.equal`) regression test: patching a run with its own hidden state must change nothing — proven true, not assumed, against both a BERT-family and GPT-2-family model before committing to the design. One caveat surfaced during implementation and documented rather than hidden: `distilgpt2` (the `main.py` demo model) is small/undertrained enough that its factual-recall signal for the demo prompt is real but noisy — a known limitation of tracing on small models, not a bug in the mechanism.
- **DEFERRED** — **Linear probing classifiers** — not attempted, for the reason already noted here: needs labeled data plus a training loop, which is a different kind of dependency than everything else in this codebase (no training loop exists anywhere in the project today).

## Phase 3 — Quantify, don't just visualize

A heatmap is not a claim you can be wrong about; a number is.

- ✅ **DONE** — **Attention entropy and attention distance per head/layer** — implemented as `BaseVisualizer.compute_attention_entropy_distance()` (+ `plot_attention_entropy_distance()`), generic across every visualizer type for the same reason rollout is. Tested against hand-computable ground truths (uniform attention → entropy `log(seq_len)` exactly; one-hot attention → entropy `0` exactly), not model-dependent approximations.
- ✅ **DONE** — **Faithfulness metrics for saliency** (comprehensiveness/sufficiency) — implemented as `BaseVisualizer.compute_faithfulness()` + `plot_faithfulness()`, for all five visualizer types. Each subclass supplies `_target_probability()` with the same target as its `compute_saliency`. A token is removed by setting its input embedding to zero, which keeps the sequence length. Tests: a mask-level test (proven to fail for a reversed sort or a missing special-token offset), exact bookkeeping identities, and a check that `p(full)` matches the plain model output. On `distilgpt2` (`main.py`), saliency (comprehensiveness AOPC 0.113) and IG (0.121) beat a random ranking (0.073). This is one prompt and one random draw: a sanity signal, not a benchmark. The sufficiency values (0.144, 0.147, 0.156) are too close to separate. Not built: a deletion-based removal mode (shorter sequence) and a built-in random baseline. `main.py` computes the random baseline itself.
- **DEFERRED** — **Cross-model comparison mode** — not attempted. This is a UX/orchestration feature, not blocked by any dependency — running two visualizers and diffing their outputs is possible today with the existing API, just not wrapped in dedicated tooling.

## Verification approach

Same discipline the bug-fix plan applies to the existing code: every new technique or architecture gets a smoke test (runs without exception on a tiny checkpoint) plus one regression test with an analytically known answer. What was actually asserted for the implemented items, in `tests/test_visualizers.py`: logit lens at the final layer exactly reproduces the model's real next-token prediction (token match + probability within `1e-5`, on `distilgpt2`); Integrated Gradients' convergence delta (the completeness-axiom gap) is asserted `< 1e-3` (empirically `~1e-8` before asserting the bound, not guessed); attention rollout's output rows are asserted to sum to `1` (a hard invariant of the construction); attention entropy is checked against hand-built uniform (`log(seq_len)`) and one-hot (`0`) synthetic attention tensors rather than real model output, since those have exact known answers a real model's attention doesn't. Silent-wrong-number bugs (like the original bug #1) are exactly what visual-only inspection misses, so pure "does it crash" smoke tests were not treated as sufficient on their own here.
